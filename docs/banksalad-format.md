# 뱅크샐러드 내보내기 형식

2026-11-04 내보내기 파일 1개를 `scripts/inspect_export.py`와 건수·비율 분석으로 확인한 결과입니다. 값은 적지 않고 구조만 기록합니다. 앱에서 내역을 수정한 뒤 다시 내보낸 결과와 연속 두 파일 사이의 키 안정성은 아직 확인하지 못했습니다.

## 메일

| 항목 | 값 |
|---|---|
| 발신 | `export-noreply@banksalad.com` (Amazon SES 서울 리전 경유) |
| 제목 | `<이름>님의 뱅크샐러드 엑셀 내보내기 데이터 (YYYY-MM-DD HH:MM:SS)` |
| 첨부 | 1개, `<이름>님_시작일~종료일.zip`, `application/octet-stream`, base64 |
| 인증 헤더 | `dkim=pass header.i=@banksalad.com`, `dmarc=pass (p=NONE ...) header.from=banksalad.com` |

- DKIM 서명은 `d=banksalad.com`과 `d=amazonses.com` 두 개입니다. 판별 기준은 `dkim=pass header.i=@banksalad.com`입니다. Gmail은 `header.d`가 아니라 `header.i`로 표기합니다.
- DMARC 정책이 `p=NONE`이고 SPF 레코드도 2개라, 발신 주소만으로는 위조를 막지 못합니다.
- `banksalad.com` 서명이 포함하는 헤더(`h=`)는 `Content-Type:MIME-Version:Subject:From:To:Message-ID:Date`입니다. **`To`가 서명되므로** 다른 사람의 내보내기 메일을 재전송해도 `To`를 내 주소로 바꿀 수 없습니다.
- `To`와 `From`은 각각 1개입니다. Gmail이 쓴 `Authentication-Results`는 그 메일에서 첫 번째로 나오는 값입니다.

## ZIP과 엑셀

- ZIP은 **ZipCrypto + Deflate**이고 안에 `시작일~종료일.xlsx` 파일 하나만 있습니다. 안쪽 파일 이름에는 실명이 없습니다.
- 엑셀 자체에는 암호가 없고 매크로도 없습니다.
- 앱에서 정한 비밀번호가 ZIP 비밀번호입니다. ZipCrypto는 약한 방식이라 **ZIP 암호를 보호 수단으로 믿으면 안 됩니다.**
- 실제 파일 크기는 ZIP 약 95KB, 엑셀 약 98KB(거래 1,836행 기준)입니다.

## 시트 1: `가계부 내역`

1행이 헤더이고, 2행부터 거래가 **최신순**으로 나옵니다.

| 열 | 형식 | 비고 |
|---|---|---|
| 날짜 | 일시 셀, 서식 `yyyy-mm-dd` | 시각 부분은 쓰지 않음 |
| 시간 | 시각 셀, 서식 `hh:mm` | **표시는 분까지지만 값에는 초가 있음** |
| 타입 | 텍스트 | `수입`, `지출`, `이체` |
| 대분류, 소분류 | 텍스트 | 수입·이체의 소분류는 모두 `미분류` |
| 내용 | 텍스트 | 가맹점이나 이체 상대 |
| 금액 | 정수 | 나가면 음수, 들어오면 양수, **0원 행 있음** |
| 화폐 | 텍스트 | 확인한 파일은 전부 `KRW` |
| 결제수단 | 텍스트 | 계좌번호 없이 상품 이름만 나옴 |
| 메모 | 텍스트 | 확인한 파일은 전부 빈칸 |

**고유 ID 열은 없습니다.** 날짜·시간·타입·내용·금액·결제수단이 모두 같은 행도 실제로 1묶음(2행) 있었으므로 순번이 필요합니다.

### 타입별 대분류

- `수입`: 금융수입, 급여, 기타수입, 용돈
- `지출`: 교육/학습, 교통, 금융, 문화/여가, 뷰티/미용, 생활, 식비, 여행/숙박, 온라인쇼핑, 의료/건강, 자동차, 주거/통신, 카페/간식, 패션/쇼핑
- `이체`: 내계좌이체, 미분류, 이체, 저축, 카드대금, 투자, 현금

### 행 표현

| 상황 | 파일에서 보이는 모습 |
|---|---|
| 카드 사용 | 결제수단=카드, 타입=지출, 음수 |
| 카드대금 | 결제수단=통장, 타입=이체, 대분류=카드대금, 음수. 내용에 카드사 이름 |
| 페이 충전 (통장 쪽) | **타입=지출**, 온라인쇼핑/결제·충전, 음수. 페이 머니 쪽 양수 행과 같은 금액, 대부분 같은 초 |
| 페이 충전 (머니 쪽) | 결제수단=페이 머니, 타입=이체, 대분류=내계좌이체, 양수 |
| 페이 충전 (출처 미상) | 결제수단=`현금`, 타입=이체, 대분류=내계좌이체, 음수. 머니 쪽 양수 행과 짝 |
| 페이 결제 | 결제수단=`… 간편결제`, `…(머니)`, `…(포인트)`, 타입=지출. 셋은 서로 다른 거래이며 중복이 아님 |
| 취소·환불 | **타입=지출, 양수.** 대부분 같은 내용·금액의 원거래와 같은 날 |
| 이자 | 타입=수입, 금융수입. 소액은 0원 행으로 나옴 |
| 본인 계좌 간 이체 | 양쪽 모두 이체, 대부분 대분류=내계좌이체. 한쪽이 대분류=이체인 경우도 있음 |

**`현금` 결제수단은 실제 현금 지갑이 아닙니다.** 출처를 모르는 입금의 짝으로 뱅크샐러드가 만든 행이 대부분입니다.

**결제수단에 없는 카드도 대금 행에는 나옵니다.** 미연동 카드는 카드대금 행이 유일한 흔적이고, 카드를 늦게 연동하면 그 이전 사용 내역은 없습니다.

## 시트 2: `뱅샐현황`

**합계 셀은 모두 수식이고 값이 저장되어 있지 않아 0으로 읽힙니다.** 총계, 월평균, 월수입 총계, 월지출 총계, 순수입 총계, 총자산, 총부채, 순자산, 각 현황의 총계가 해당합니다. 합계는 항상 직접 계산합니다.

행 번호는 보유 상품 수에 따라 달라지므로 **구역 제목으로 위치를 찾습니다.** 내용은 B열부터 시작합니다.

| 구역 제목 | 구조 |
|---|---|
| `1.고객정보` | 이름, 성별, 연령, 신용점수, 이메일. **이 앱은 읽지도 저장하지도 않습니다.** |
| `2.현금흐름현황` | B=항목, C=총계, D=월평균, E부터=월(`YYYY-MM` 텍스트). 수입 대분류 행, `월수입 총계`, 지출 대분류 행, `월지출 총계`, `순수입 총계` 순서 |
| `3.재무현황` | "데이터를 내보낸 시점"의 자산과 부채. 자산 B=항목, C=상품명, E=금액 / 부채 F=항목, G=상품명, I=금액. 항목 칸은 그룹의 첫 행에만 있음 |
| `4.보험현황` | 금융사, 보험명, 계약상태, 총납입금, 계약일자, 만기일자 |
| `5.투자현황` | 투자상품종류, 금융사, 상품명, 투자원금, 평가금액, 수익률, 가입일자, 만기일자 |
| `6.대출현황` | 대출종류, 금융사, 상품명, 대출원금, 대출잔액, 대출금리, 대출신규일, 대출만기일 |

자산 항목은 자유입출금 자산, 신탁 자산, 현금 자산, 저축성 자산, 전자금융 자산, 투자성 자산, 부동산, 동산, 기타 실물 자산, 보험 자산, 연금 자산입니다.

### 내역과의 관계

- **현금흐름 표의 대분류×월 칸은 해당 타입·대분류·월의 금액 합계 절대값과 정확히 일치합니다** (확인한 파일의 모든 칸). 지출 칸은 양수로 표시되고 취소·환불이 차감된 값입니다. 가져오기 검증에 씁니다.
- 뱅크샐러드의 지출 합계에는 페이 충전 출금도 들어 있어 페이 사용과 **이중 집계**됩니다. 대금으로만 보이는 미연동 카드 사용은 빠져 있습니다.
- 자유입출금·저축성·현금 자산의 상품명은 결제수단 이름과 정확히 일치합니다. 계좌별 잔액을 결제수단에 연결할 수 있습니다. 전자금융 자산은 이름이 달라 자동으로 연결되지 않습니다.

## 설계에 반영한 변경

| 계획 | 실제 파일을 본 뒤 |
|---|---|
| 총액 = 카드 + 계좌 + 기타 | **총액 = 카드 + 계좌 + 페이 + 기타.** `간편결제` 행은 어떤 카드나 계좌로 결제했는지 알 수 없어 페이로 따로 둡니다. |
| 페이에 연결한 카드 결제는 카드로 귀속 | 행에서 판단할 수 없어 페이로 표시합니다. 같은 금액 쌍을 분석했을 때 카드 행과 페이 행의 중복은 나타나지 않았습니다. |
| DKIM은 `header.d`로 확인 | `header.i=@banksalad.com`과 `dmarc=pass`로 확인하고, `To`가 내 주소 하나인지도 봅니다. |
| 합계 대조는 게이트 또는 경고 | 모든 칸이 일치하므로 **불일치 시 격리**합니다. |
| 자동 분류를 기본값으로 신뢰 | 큰 금액의 분류가 어긋나는 경우가 있어 금액순 검토함을 v1 필수로 둡니다. |
